01 / What slop is

A shared house style nobody chose

Slop is the statistical mean of a billion training examples: the shadcn palette, the ChatGPT register, the centered hero with three feature cards. Escaping it costs a deliberate decision. The default is sameness.

You can spot it in four places at once. In visual design, a purple-to-pink gradient over Inter, a colored strip down the left edge of every card. In UX, a happy path with no empty state, an icon button with no label. In copy, "in today's fast-paced world," a hedge stacked on a hedge. In code, an empty catch block, a comment that just restates the next line.

None of it is broken. That's the trap. It passes review, it renders, it ships, and it looks like everything else. This guide is the style-agnostic layer that sits on top of whichever design style a build uses: the per-style checklists judge fidelity to their style, and this one catches the generic-AI baseline no matter which style you picked.

02 / How it works

Two layers: steer the build, then scan it

One layer works while you generate. The other checks what came out. Neither replaces judgment; both make the generic default expensive to ship by accident.

01Prevention · while building

A playbook that steers the work

The one rule above all Write a short DESIGN.md first: a project-specific palette, a distinctive type pairing, a voice. Generate against that file, not against muscle memory. Negative constraints beat positive adjectives.

52 ranked rules follow, phrased as "the slop / do instead / why," so a fix is a decision you can act on, not a vibe. Every rule is browsable below.

02Detection · before shipping

A linter that scans the output

slopcheck is a zero-dependency Python 3 CLI. It reads a signature ruleset and scans built files for 66 machine-detectable tells, then reports where to look. A match is a prompt, not a verdict.

It defaults to medium-and-up severity and hides the high-false-positive rules, so the signal stays high on real work. Run it by hand, wire it into CI, or attach the optional per-project hook.

03 / Running the detector

Advisory by default, a gate when you want one

The same tool serves three depths: a quick local scan, a strict pre-ship sweep, and a CI gate that fails the build on a high-severity tell.

# scan the current tree: medium+ severity, low-noise defaults
skills/design-antislop/slopcheck src/

# the full sweep for a hero or primary flow: adds high-false-positive rules
skills/design-antislop/slopcheck --strict index.html

# narrow the lens
skills/design-antislop/slopcheck --dimension copy --min-severity high

# machine output for CI, and inspect the active ruleset
skills/design-antislop/slopcheck --json
skills/design-antislop/slopcheck --list
exit 2
At least one high-severity tell. Usable as a hard CI gate.
exit 1
Medium or low findings only. Worth a look, not a block.
exit 0
Clean at the chosen severity. Ship it.
hook
Opt-in per project: surfaces high tells on each edit, never blocks. Off globally on purpose, since empty-catch fires on normal backend work.

05 / Provenance & honesty

Heuristics, not laws

"The canonical tell flipped from signature to liability in about a year."

The ruleset was distilled on 2026-08-18 by the anti-slop-research fleet: twelve finders across GitHub, Reddit, and design writing, hundreds of findings pressed down to 66 signatures and 52 rules. The raw material is kept, so the list is meant to be re-run, not frozen.

It has to be. Anthropic's own frontend guidance now excludes the purple-on-white gradient it once reached for by default. Slop tells rot: what marks a machine this year can be a deliberate choice the next. So treat every match as "look here," never "this is wrong." The linter is advisory. Human judgment ships the work, and no invented statistic about slop belongs in it.
